# Проверка безопасности оплаты и доступа — 03.10.2026

## Итог

Публичный GitHub Pages — демонстрация: заявки сохраняются в браузере, оплата и видео не подключены. Переносимый сервер `server/` принимает заявки и позволяет вручную сверить банковский QR, но **не является готовой автоматической продажей курса**. В этой проверке усилены админский процесс подтверждения, исправление ошибочного email, учёт возвратов и защита от случайной публикации видео. Банковскую интеграцию, проверку владения почтой и закрытую выдачу видео ещё необходимо подключить до продажи доступа.

## Высокий риск / блокеры запуска видеопродаж

### SEC-01 — Нет автоматического подтверждения зачисления денег (High)

- **Место:** `server/app.mjs:85`, `server/config.mjs:12-16`, `server/store.mjs:46-63`.
- **Доказательство:** вебхук возвращает 501; режим оплаты ограничен `disabled`/`manual-qr`; подтверждение делает вошедший администратор.
- **Влияние:** скриншот или сам факт сканирования QR не доказывает платёж. Администратор может ошибочно подтвердить заказ или его учётная запись может быть скомпрометирована.
- **Исправлено сейчас:** сервер игнорирует присланный клиентом статус/цену; для ручного подтверждения требуется банковский номер операции, отметка о проверке в банке, уникальность номера, допустимый переход состояния и запись в журнал. Старые подтверждения без номера переводятся на повторную сверку миграцией `002`.
- **Осталось:** реальный банк/провайдер, проверка подписанного уведомления и/или запрос статуса в API банка, сверка суммы/валюты/получателя и идентификатора заказа, идемпотентная обработка событий. Пока этого нет, **не делать автоматическую выдачу доступа по статусу формы**.
- **Уточнение:** уникальный текстовый номер и чекбокс не являются криптографическим доказательством платежа.

### SEC-02 — Нет закрытой системы выдачи платных видео (High)

- **Место:** `pages/course.html:37-72`, `server/app.mjs:130-145`, `.github/workflows/pages.yml:37-57`.
- **Доказательство:** на странице только постеры/заглушки; нет видеофайлов, сессии ученика и защищённого видеомаршрута. GitHub Pages публичен по своей природе.
- **Влияние:** если положить платный файл в публичную папку или бакет, ссылку можно передать без оплаты; скрытая кнопка не защищает файл.
- **Исправлено сейчас:** CI отклоняет видеофайлы в `pages/` и `public/`; сервер не обслуживает видеоформаты и тест проверяет 404 для прямого URL.
- **Осталось:** приватное хранилище вне публичных каталогов, вход ученика, проверка владения почтой и права на каждый видео-GET/Range-запрос по подтверждённой оплате и сроку тарифа. Возврат должен отзывать это право. Даже после внедрения защита не устранит запись экрана.

### SEC-03 — Введённая почта не подтверждает владение адресом (High перед выдачей доступа)

- **Место:** `pages/index.html:187-188`, `pages/payment.js:39-42`, `server/store.mjs:65-78`.
- **Доказательство:** два одинаково введённых адреса проверяют опечатку, но не доказывают, что ящик принадлежит покупателю.
- **Влияние:** если автоматически отправить доступ по введённому email, его может получить посторонний при ошибке или умышленной подмене.
- **Исправлено сейчас:** повторный ввод и серверная проверка совпадения; исправление адреса только администратором после сверки банковской операции, с причиной и журналом. Исправление **не** отправляет доступ.
- **Осталось:** одноразовое подтверждение нового адреса через рабочий почтовый сервис и отдельная проверка плательщика. Не использовать одно знание номера заявки или адреса как доказательство владения покупкой.

## Средний риск / рабочие сценарии

### SEC-04 — Возврат нужно отличать от запроса на возврат (Medium)

- **Место:** `server/payment-policy.mjs:3-17`, `server/store.mjs:46-63`, `public/course/legal-documents.json:859-946`.
- **Доказательство:** ранее были только `pending/confirmed/rejected`.
- **Влияние:** нельзя было учесть запрос, зафиксировать банковский возврат и обеспечить будущий отзыв доступа.
- **Исправлено сейчас:** состояния `refund_requested` и `refunded`, обязательный номер операции возврата и запись в журнал; после `refunded` повторное подтверждение запрещено. В интерфейсе явно сказано, что рассмотрение запроса не равно возврату денег.
- **Осталось:** фактический возврат делает банк/провайдер; решение о сумме и сроке принимается по условиям договора и закону, не по автоматическому таймеру. Когда появится личный кабинет, возврат должен отзывать действующие сессии/права на видео.

### SEC-05 — Старая Cloudflare/Next-ветка не равна текущему переносимому серверу (Medium, если её развернуть)

- **Место:** `db/users.ts:135-181`, `app/course/page.tsx:22-25`, `app/course-preview/page.tsx:7`.
- **Доказательство:** там отдельная база пользователей и админское ручное `approve/grant`; публичный preview курса содержит заглушки. Эта ветка не обслуживает текущий GitHub Pages и не связана с PostgreSQL-сверкой из `server/`.
- **Влияние:** запуск двух реализаций может создать несогласованные статусы и ошибочную выдачу доступа.
- **Решение:** для переноса текущего дизайна использовать только путь из `docs/hosting-launch.md`; не считать старый Next-механизм подтверждением реальной оплаты и не загружать туда видео до отдельной проверки.

## Проверенные защитные меры

- Сервер устанавливает сумму из фиксированного тарифа и сохраняет подтверждения редакций документов (`server/app.mjs:67-78`).
- Админский API требует сессию, Origin и CSRF; публичная форма ограничена по частоте (`server/app.mjs:20-34,57-58`).
- PostgreSQL использует параметризованные запросы, уникальные банковские номера и транзакцию при смене статуса (`server/store.mjs:46-78`).
- QR отдается из локальных файлов с фиксированными именами; URL клиента не используется для загрузки файлов (`server/config.mjs:14-16`, `server/app.mjs:80-84`).
- На сервере заголовки CSP, `nosniff`, запрет фреймов и `no-store` (`server/app.mjs:45-53`).

## Обязательное перед открытием продаж

1. Выбрать и проверить банковский QR/эквайринг; для автоматической выдачи — интегрировать подтверждение статуса по официальному API банка, не по редиректу клиента.
2. Подключить проверку email и закрытое видеохранилище. Видео не класть в GitHub Pages, `pages/`, `public/` или доступный извне контейнер.
3. Проверить выдачу чека/фискализацию и порядок возвратов с банком/бухгалтером и юридическим специалистом. Не менять права покупателя на возврат технической блокировкой.
4. Укрепить админский вход для финансовых действий (MFA/отдельный фактор) перед продакшеном; защищать и резервировать базу с персональными данными.
5. Провести тесты на реальной инфраструктуре: неоплаченный/поддельный/дублированный платёж, неверный email, возврат, повторное воспроизведение URL, окончание годового срока «Стандарт».
